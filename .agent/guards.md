# 护栏：哪些约定已经被机器兜住了

这份文档只回答一个问题：**「这条规矩我写进文档了」和「这条规矩破不了」之间差多少。**

`.agent/AGENTS.md` 与 `conventions.md` 里大量约定是**口头**的（「调接口一律走
`src/utils/api.ts`」「模板只负责渲染」）。文档会被读一次，代码会被改一百次 ——
约定必须有机器版本，否则它只是建议。

本文件登记**已经落地成可失败断言**的约定，以及它们的**证明方式**。
新增护栏时按同样格式追加：规则 → 拦什么 → 怎么证明它真的会拦。

> 判定标准只有一条：**如果功能/约定是坏的，这条会红吗？**
> 不确定的护栏一律按「没这条护栏」算。

## 一、ESLint 分层依赖（`eslint.config.js`）

| 规则                                                                          | 拦什么                    | 为什么                                                                                                                  |
| ----------------------------------------------------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `src/templates/**` 禁止 import `@/stores/*`、`@/composables/*`、`@/utils/api` | 模板里注入状态机或发请求  | 同一套模板被编辑器、分享页 `/share/:id`、PDF 渲染服务三处复用。模板一旦拿到 store，公开分享页会连带加载整个编辑器状态机 |
| `src/utils/**` 禁止 import `@/components/*`、`@/stores/*`、`vue`              | 纯逻辑层被拖进 Vue 运行时 | `src/utils` 在 Node 里被 `tests/` 直接 import；引了组件就必须装 DOM 桩                                                  |
| `src/components/**`、`src/pages/**`、`src/composables/**` 禁止裸 `fetch`      | 手写网络请求              | 本项目曾有 20 处手写 fetch，演变成四五种错误语义（有的抛 `.code`、有的返回 null、有的静默返回空数组）                   |
| `src/**` 禁止 `console.log` / `console.error`（只允许 `console.warn`）        | 调试输出留在线上          | 浏览器控制台没有任何采集，用户看不到也没人看得到。需要提示用户的走 `useToast`                                           |

**两处具名豁免**（`src/templates/index.js`、`src/utils/avatarStore.js`）：
那里的 `console.error` 是**降级路径的信号** —— 模板 chunk 加载失败回退经典单栏、
IndexedDB 不可用回退内联存储。两者在界面上都没有任何变化，只有控制台能说明原因。
豁免是具名的、有注释的，不是「整目录关掉」。

### 证明它会拦（改动护栏后必须重做一次）

```sh
# 1. 模板不该引 store
#    在 src/templates/ClassicTemplate.vue 的 import 段加一行：
#      import { useResumeStore } from '@/stores/resume'
#    期望：npm run lint 报 no-restricted-imports → 删除该行后恢复通过

# 2. 组件不该裸 fetch
#    在 src/composables/useMediaQuery.js 末尾加：
#      const probeNet = () => fetch('/api/health')
#      export { probeNet }
#    期望：npm run lint 报 no-restricted-globals → 删除后恢复通过
```

两条都**实际执行过**（2026-10-23，结果分别为 1 error / 1 error，恢复后 exit 0）。

## 二、文档漂移（`tools/check-agent-docs.mjs`）

它把 `.agent/` 四份文档里**可机械核对**的断言抽出来跑：内部链接可达、提到的
`npm run X` 脚本存在、`conventions.md` 声称的「N 个 `.js` 不受类型检查」与工作区实际数量一致。

**它自己就是一次踩坑的产物**：曾经用 `git ls-tree HEAD` 数已提交的 `.js`，
于是「迁完 TS 但还没提交」时脚本照样报一致，CI 才红。

**这次它抓到的两处漂移已经修掉**：一是 `conventions.md` 的 `.js` 总数（写 22、实际 22，
但分布表里 `selection` 与 `history` 的位置写错了名字）；二是 `README.md` 声称的
「67 / 67 组件全部完成」，实际是 68 个。第二次是典型的分母错误 ——
组件加了一个，分数没跟着加。

它的覆盖边界要说清：**它只比总数，不比分布表里的文件名**。
所以分布表改了以后，要自己数一遍「点名个数 = 该行数量」，
以及「各行之和 = 底部总数」。上一版就是总数对、分布错。

## 三、规则引擎与「表达助手」（`src/utils/expression.ts`）

要点级的写作检查是**纯函数**，43 例单测覆盖规则与时间解析；界面上的
「点了会打开」「断网仍然可用」「一键替换真的改到原文」由 `tools/verify-expression.mjs`
（真浏览器）保证：

```sh
npm run dev
node tools/verify-expression.mjs        # 18 项，含断网断言
```

**写这个脚本时踩过的四个坑，都记在脚本头部注释里** —— 每一个都会让断言
「看起来绿、其实没测到」：

1. 新手引导的 `role="dialog"` 会抢在真正要验的弹窗前面被选中 → 先关掉，并**确认关掉了**；
2. 面板顶部的锚点胶囊只滚动、不展开卡片 → 一条要点都拿不到；
3. 模块标题是 `<input value="工作经历">`，**不在 `innerText` 里**，
   `locator.hasText('工作经历')` 永远匹配不到 → 必须按 `input.value` 找索引；
4. `evaluate` 里直接赋值 `textarea.value` 绕过了 Vue 的 `v-model`，
   「改写原文」实际没生效 → 一律用 Playwright 的 `fill()`。

规则引擎自身也被测试抓出过三个真 bug（都已修，并留了回归断言）：

| 症状                                  | 真因                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------- |
| `2022 - 2024` 解析成「2022 年 20 月」 | 日期正则的年份没有数字边界，`- 20` 被当成「年-月」的分隔                    |
| 两条**逐字相同**的要点反而不报重复    | 用 `norm(a) !== norm(b)` 排除自身，而 norm 会把全角转半角，两次结果永远相等 |
| 界面上显示「命中：负责负责负责」      | `WEAK_VERBS` 里「负责」出现三次（三种改法），扫描时同一位置被扫了三遍       |

## 四、可观测性（`server/requestGuards.ts` / `server/index.ts`）

| 护栏                                                        | 证明方式                                                                                                  |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 每个 `/api` 响应都带 `X-Request-Id`，且写进那一行 JSON 日志 | `tests/api.test.js`「每个 /api 响应都带 X-Request-Id，且每次不同」（已做反向验证：去掉 `setHeader` 即红） |
| 启动横幅第一行带 node 版本与 pid、第二行打实际 DB 路径      | 真启动一次看输出（只打路径不打内容）                                                                      |

请求 ID 的用途：用户报「我那次导出失败了」时，让他从浏览器网络面板复制这个值，
就能在几百行日志里精确找到那一条 —— 这正是过去做不到的事。

## 五、还没被机器兜住的（诚实清单）

写下来，免得后来者以为「文档写了就等于做了」：

| 约定                         | 现状                                      | 缺口                                                                     |
| ---------------------------- | ----------------------------------------- | ------------------------------------------------------------------------ |
| 新增简历字段要动四处         | `tests/sanitize.test.js` 覆盖白名单行为   | 没有断言「`src/types/resume.ts` 的字段 ⊆ `server/sanitize.ts` 的白名单」 |
| 模板内联事件只写单条语句     | 只有 `npm run build` 会炸                 | CI 有 build，算半兜住；但本地 `npm run check` 不含 build                 |
| 界面样式只消费 `--ed-*` 令牌 | `tools/audit-ui.mjs` 量对比度             | 不检查「是否写了颜色字面量」                                             |
| `format:check` 必须是绿的    | 已进 CI                                   | 但 `tools/**` 不在检查范围内，新写的脚本可能格式漂移                     |
| 服务端能真启动               | CI 已加「启动 + 打 `/api/health`」        | 只验健康检查，不验导出端点                                               |
| `verify:*` 脚本本身正确      | 各自头部注释记了坑                        | 没有「脚本自身」的回归测试；改了界面文案后脚本会一起失效（这是有意的）   |
| 提示词里「允许模型不改」     | `tests/aiClient.test.js` 断言「原样返回」 | 只断言文案在位；断言不了模型真的照做                                     |
| 体检总数角标要诚实           | `tests/completeness.test.js` 按处数断言   | 界面上「角标数字 = 弹窗处数之和」没有浏览器级断言                        |

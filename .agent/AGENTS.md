# AGENTS.md — AI 协作入口

你是要在这个仓库里改代码的 AI。**先读这一页，再动手。** 这一页只讲三件事：
哪些东西必须先读、哪些地方最容易出错、改完必须跑什么。

---

## 一、动手前的强制顺序

按顺序读，不要跳。**跳过第 3 步是本项目历史上最贵的错误来源。**

| #   | 读什么                             | 为什么                                          |
| --- | ---------------------------------- | ----------------------------------------------- |
| 1   | 本文件（`AGENTS.md`）              | 规则与命令都在这里                              |
| 2   | [`../README.md`](../README.md)     | 产品形态、页面结构、目录树、各脚本做什么        |
| 3   | [`../PITFALLS.md`](../PITFALLS.md) | **603 行踩坑记录。不读它就会重犯别人的错误**    |
| 4   | 你打算改的那个文件本身             | 不要凭对结构的想象动手 —— 见 `PITFALLS.md` E 类 |

第 4 步之所以单列：本项目真实发生过「凭印象改了一个本来正确的 flex 规则」和
「差点把已经能用的纸面拖拽当成坏的再修一遍」。**改之前先读文件，改完用 `git diff` 核对。**

## 二、三条最容易被 AI 违反的规矩

这三条不是风格问题，是这个仓库里反复付出代价的地方。

### 1. 验证脚本报错时，先怀疑脚本

`PITFALLS.md` 的 A 类有 **18 条**，全是「验证工具报错，被测对象其实没错」，
比其它五类加起来还多。光「探针落点不对」一条就栽过 4 次。

**实际后果不是浪费时间，是去"修"本来正确的代码。**

落到操作上：

- 探针报「功能坏了」→ 先确认**它真的点到了**那个元素（截图 / `boundingBox` / `elementFromPoint` 复核）。
- 元素坐标不对 → 先确认**滚动没让坐标失效**（滚完要重新取一次位置）。
- 页面上找不到元素 → 先确认**它那一刻是否被 `v-if` 藏了**、是否在别的 tab/视图里。
- 报告是「0 问题」→ 先确认**覆盖是真的**（分母是多少？有没有静默的上限？）。

### 2. 不要写出"看起来通过、其实没测到"的测试

这条比写错代码更危险，因为错代码会失败，假通过的测试不会。

本项目真实踩过的形态：

- 窄屏验证时元素被 `v-if` 隐藏，拿不到就写成「跳过」并判 PASS —— 那不是通过，是没测。
  **拿不到就判 FAIL，不要判跳过。**
- 用 PowerShell 时把承接令牌的变量也命名为 `$cookie`，导致审计**静默按未登录跑了一遍**，
  报出漂亮的「0 问题」，而管理后台根本没渲染。
- 只比较 `background-color` 会把渐变按钮判成「无变化」，主按钮因此躲过第一版审计。

**规矩：一个断言要能失败。** 写完后问自己「如果功能是坏的，这条会红吗？」答案不确定就重写。

### 3. 静默失效优先于报错

这个项目里最难查的 bug 全是**不报错**的那种：

- `scrollMode: 'if-needed'` 不是标准属性 → 浏览器直接忽略，注释承诺的行为从来没生效过。
- `<input>` 是替换元素，`::after` 不生效 → 命中区扩了个寂寞。
- `shallowRef(null)` 被推成 `Ref<null>` → 读 `.value.x` 才报错，位置离真因很远。

所以：**改完要看效果，不要只看"没报错"。** 界面改动至少截图或跑一次对应的 `verify:*`。

## 三、命令

```sh
npm ci && npm ci --prefix server   # 两份独立依赖，缺一不可

npm run dev:all     # 前端 5173 + 后端 3001，开发推荐
npm run dev         # 只前端
npm run pdf         # 只后端（托管 dist + /api）

npm run check       # typecheck + lint + test，提交前跑这个

npm run lint
npm run typecheck   # 必须单独跑：Vite 只转译不做类型校验
npm test
npm run build
npm run format:check
```

**验证脚本**（`verify:*` / `audit:*`，共 30+ 个）需要先有一个跑着的站点，
但**默认地址不是统一的** —— 实测分成两半，别猜：

| 默认连哪         | 要求                                              | 脚本                                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `localhost:5173` | 先 `npm run dev`                                  | `verify:drag` `verify:paper` `verify:drag-ux` `verify:panel` `verify:selects` `verify:markdown` `verify:pdf` `verify:pages` `verify:spacing` `verify:toolbar` `build:host-template` `shoot-drag-state` |
| `127.0.0.1:3001` | 先 `npm run build` + `npm run pdf`（托管 `dist`） | `audit:ui` `audit:interaction` `audit:el` `audit:admin` `verify:templates` `verify:dialogs` `verify:captcha` `probe:perf` `probe:mobile` `probe:session` `audit:trace` `shoot-pages` `shoot:dialog`    |
| 两者皆可         | 有站点即可                                        | `audit:scroll`（右侧面板滚动流畅度，**两个页签都会量**）                                                                                                                                               |

两者都支持用第一个 `http://...` 参数覆盖默认地址。连错了会得到 `ERR_CONNECTION_REFUSED`——
那不是代码坏了。

**动过 CSS 影响滚动性能时跑 `npm run audit:scroll`。** 它分段量内容页签与设计页签的
滚动帧间隔，并单独报「冷启动」—— 一次性成本（`content-visibility` 首次渲染）
不会混进分段 p95 里。设计页签必须单独量：它比内容页签短得多却更卡（密度问题），
只测内容页签会漏掉它（见 `PITFALLS.md` D6/D7）。

### 上面那张表**不是全部前提**，它只解决"连哪个端口"

有几个脚本还各自需要额外条件，**漏了会得到"覆盖面严重缩水"的绿报告**：

| 脚本             | 额外前提                                                   | 漏了会怎样                                                                                                           |
| ---------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `audit:ui`       | 要带 `--token <会话令牌>`（用 `npm run audit:login` 生成） | **只量到未登录界面**，而模块面板 / 设计面板 / 管理页都要登录才渲染 —— 恰恰是问题最集中的地方。会得到漂亮的「0 问题」 |
| `verify:pdf`     | `.env` 里要有 `PDF_ACCESS_PASSWORD`（走 Bearer 通道）      | 无法通过认证。它自带 `pdf-harness` 起独立实例，所以**不依赖 3001**，但仍需要 5173 在跑                               |
| `verify:selects` | 若审 3001，`dist` 必须是最新的                             | 对着旧产物验证，得出「改动没生效」的错误结论（脚本内有 `assertDistFresh()`）                                         |
| 导出类验证       | 别连生产实例反复跑                                         | 双层配额会被验证吃掉，当天真实导出失败                                                                               |

**这就是为什么「跑之前先读脚本头部注释」不能省。** 上面这张表已经踩过一次坑：
第一版只有端口表、没有这张前提表，而端口表看起来足够完整，反而让人不去读注释。

## 四、这个项目最容易改错的地方

按「AI 最可能踩」排序，详细理由见 `PITFALLS.md` 与 `README.md`。

| 位置                   | 陷阱                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/**` 的相对导入 | **必须写全 `.ts` 扩展名**（`./auth.ts`），且类型导入必须 `import type` —— 否则剥离后运行时找不到导出                                        |
| 新增简历字段           | 只改前端不生效：`src/types/resume.ts`、`src/data/normalizeResume.ts`、`server/sanitize.ts` **三处都要动**，服务端白名单会静默丢弃未登记的键 |
| 模块布局               | 上下方向叠加主题 `--gap`（`calc`），左右是纯 `padding`。**零值不要输出内联样式**，否则盖掉主题默认值                                        |
| 模板样式               | `src/templates/**` 里的配色是**简历内容自身的颜色**，刻意不接设计令牌 —— 改了会影响用户导出的简历                                           |
| 界面样式               | 一律从 `src/styles/paper.css` 的 `:root` 令牌取值，不要写颜色/圆角字面量                                                                    |
| 模板内联事件           | 只写**单条语句**，多动作包成函数。多语句会被 Prettier 折行，Vue 编译器解析失败，**lint 和 typecheck 都不报，只有 build 会炸**               |
| 测试里的 DOM           | **不要**全局装 `document`（pdf.js 会误判运行环境）。需要时用 `tests/setup/browser-globals.js` 成对开关                                      |
| 渲染目标               | PDF 导出靠打开真实 `/editor` 页面，改动 `EDITOR_PATH` 或等待选择器会静默导出空白页                                                          |

## 五、改完必须做的事

1. `npm run check`（typecheck + lint + test）。
2. 触及界面 → 跑对应的 `verify:*`，或至少截图看一眼。
3. 触及 `server/**` → **真启动一次**（`npm run pdf`）确认能起来。
   本项目有个 500 的 bug 就是这么发现的：导出端点误用了只支持会话通道的访问器，
   单测不会发现，因为 `/api/pdf` 没有集成测试。
4. `git diff` 逐行核对 —— 尤其确认 lint-staged 没帮你改了别的地方。
5. 新踩的坑 → 记进 `PITFALLS.md`（症状 / 真因 / 规矩三件套，缺一不可）。

**没有真实运行证据的「已修复」不要写。** 这个仓库的规矩是：跑过就是跑过，没跑就说没跑。
